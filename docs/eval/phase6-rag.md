## Analysis (hand-written)

Both configs make every test pass, so **resolve rate does not separate them here** —
the difference is *where* the fix lands. Without retrieval the planner only sees file
names and chose the caller in 3/5 cases, producing workarounds that leave the real
bug in place for every other caller:

- `textkit-slug` → lowercased the URL in `textkit/urls.py`; `slugify()` still keeps uppercase.
- `feature-flags` → added a private `_is_truthy()` in `app/features.py` and stopped using the
  shared `parse_bool()`, which still treats `"false"` as true.
- `weekly-report` → reimplemented `_monday_start()` in `reports/weekly.py`; `week_start()`
  is still off by one.

With retrieval the agent saw the helper's code and fixed the root cause in 5/5, using
~20% fewer tokens on average. An earlier attempt at this run (before 429 rate-limit
retries were added) also had no-RAG localize `feature-flags` to `app/__init__.py` and
fail all 3 attempts — temperature 0 is not fully deterministic on this provider.

Caveats: 5 hand-made cases, one trial each at temperature 0 — a smoke-level signal, not a benchmark. The real measurement is Phase 7 (SWE-bench Lite).
