# CLAUDE.md — Start here (for any coding agent)

You are working on **DevPilot**: an AI agent that takes a real GitHub issue,
inspects a repo, plans a fix, writes a patch, runs the repo's tests in an
isolated Docker sandbox, shows the diff, and — only after human approval —
opens a pull request. Scoped as a **portfolio project, not a commercial product.**

## The 9 phases (see docs/PLAN.md for detail)
1. Finish backend foundation · 2. **Walking skeleton — whole agent loop, minimal** (most important) ·
3. Frontend + light auth · 4. Real GitHub integration · 5. LangGraph agent ·
6. Repository RAG · 7. Evaluation on SWE-bench Lite · 8. One MCP server + Langfuse · 9. Deploy + polish.

**Explicitly out of scope** (do not build): Kubernetes/Terraform, full
Prometheus/Grafana/OTel, multi-tenancy/accounts/billing/RBAC, managed cloud
sandboxes, GitHub App with per-install tokens. A fine-grained PAT + local Docker
are sufficient.

## Golden rules (summary of rules.md)
- Inspect the real checkout + `git status` + `alembic current` before editing; docs may lag.
- Work in small, tested vertical slices. Never claim a check passed unless you ran it.
- `router → schema → service → SQLAlchemy → PostgreSQL`; keep routers thin.
- Alembic for every schema change; review autogenerated migrations. Never run destructive DB commands without verifying the database.
- Keep `.env`, keys, and tokens out of Git. Tests use a **dedicated** test DB.
- Treat model/repo/tool/issue content as **untrusted**; run repo code only in the sandbox, never on the API host. Require human approval before opening a PR.

## Working directory & commands
Backend: `apps/api` (with `.venv` active). Frontend: `apps/web`.

```bash
# backend
cd apps/api && source .venv/bin/activate
pytest -v && ruff check . && ruff format --check .
alembic upgrade head && uvicorn app.main:app --reload
# frontend
cd apps/web && npm install && npm run dev
```
Repo root: `make check` (backend lint+format+tests), `make docker-up` (Postgres+API).

## Definition of done
Behavior implemented → input validated → tests + lint/format pass → docs updated (at least `memory.md`) → secrets excluded → diff reviewed. No empty commits.
